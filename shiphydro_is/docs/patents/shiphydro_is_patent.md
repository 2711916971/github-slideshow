# 一种面向船舶流体设计与工业软件协同的多目标优化系统及方法

## 技术领域

本发明涉及船舶流体力学设计、计算流体力学仿真与工业软件协同集成领域，具体是一种支持参数化船体建模、网格生成、CFD求解与代理模型驱动优化协同的多目标优化系统及方法。

## 背景技术

船舶设计涉及跨平台的CAD、网格与CFD求解器。现有流程中存在以下痛点：

1. **跨软件耦合难**：不同厂商软件接口差异大，缺乏统一调度与安全隔离。
2. **成本高**：重复网格与仿真造成资源浪费；多套许可证维护成本高。
3. **迭代慢**：缺乏自动化主动学习与缓存机制，设计迭代周期长。
4. **不确定性大**：代理模型与真实CFD耦合缺少闭环校核，难以评估可靠性。

## 发明内容

本发明提出的 ShipHydro-IS 系统包含统一适配层、主动学习闭环、哈希缓存复用、干跑审计、安全沙箱及代理+CFD分层评估机制，实现可审计、可追溯的多目标优化流程。系统架构分为数据层、服务层、适配层、任务编排层与界面层：

- **统一 Adapter 层**：封装 OpenFOAM、Fluent、Star-CCM+ 等求解器，支持命令行、文件交换、Python API 与 REST 协议，提供干跑模式输出命令与脚本用于安全审计。
- **主动学习闭环**：在代理模型预测的不确定度基础上触发新工况仿真，实现代理与高保真求解闭环迭代。
- **哈希缓存复用**：基于几何、工况与求解器版本的 SHA256 哈希，实现几何、网格、仿真结果的重复利用，缩短迭代时间。
- **安全沙箱与审计**：对外部命令执行应用白名单与路径沙箱，所有任务在受控容器内运行并记录审计日志。
- **分层评估**：先使用代理模型筛选 Pareto 候选，再触发真实 CFD 校核，兼顾效率与精度。

## 具体实施方式

1. **几何模块**：
   - 几何 DSL 采用 YAML 定义主尺度（Lpp、B、D、Cb）与球鼻艏参数，解析后生成 NURBS 灵感截面并导出 STL。
   - 导入模块支持 STEP/IGES/STL，若缺乏第三方库则使用 mock 解析顶点并校验尺寸。
   - 校验器执行尺度、法向一致性与孔洞检查，必要时给出修复建议。

2. **网格与求解模块**：
   - 默认生成 OpenFOAM case 结构，包含 controlDict、fvSchemes 等模板文件。
   - 运行器按 blockMesh→snappyHexMesh→simpleFoam 调度，若命令不可用则切换至 mock 求解器生成可重复伪数据。
   - 结果解析器提取 forces.dat、residuals，计算 Rt、Ct、sinkage 等指标。

3. **任务编排模块**：
   - 基于本地或 Celery 队列的任务模型，支持 MeshTask、SolveTask、PostTask、ALTask，具备重试、超时、取消与心跳。
   - 利用审计日志记录每次外部命令与参数。

4. **代理模型与主动学习**：
   - 通过 Kriging、RBF、GPR、XGBoost 及 POD-ROM 对 Rt、波浪兴波、稳性指标进行预测。
   - 不确定度模型输出置信区间，主动学习策略在设计空间中选择最大不确定或期望改进值。

5. **多目标优化模块**：
   - 实现 NSGA-II 与贝叶斯优化组合流程，约束稳性与排水量，目标最小化 Ct 与波浪兴波。
   - 候选经代理筛选后自动触发真实 CFD 校核。

6. **数据与版本管理**：
   - 元数据存储于 PostgreSQL/SQLite，工况与几何以哈希索引；大文件存储在 MinIO/本地 artifacts。
   - 与 MLflow 集成记录代理与优化实验。

7. **前端界面**：
   - Geometry Lab 提供参数化表单与 3D 预览，Case Builder 用于编辑工况并提交任务，Run Monitor 展示 KPI 与收敛曲线，Optimization 显示帕累托前沿与候选。

8. **部署与安全**：
   - Docker Compose 集成 backend、frontend、openfoam-mock、数据库、对象存储与 Redis，支持 K8s 扩展。
   - 提供 `/metrics` Prometheus 接口与 JSON 日志格式，满足审计要求。

## 有益效果

- 缩短 CFD 迭代时间，降低高保真仿真次数。
- 通过统一适配层提升跨软件协同效率，强化安全性与可审计性。
- 主动学习闭环提高代理模型精度并降低不确定度。
- 哈希缓存减少重复计算与存储成本。

## 代码清单索引

- `backend/adapters/geometry/`：实现几何 DSL、生成器与校验器。
- `backend/adapters/cfd/`：实现 OpenFOAM 案例写入、运行器、mock 求解与结果解析。
- `backend/app/`：FastAPI 接口 `/api/v1/jobs`、`/api/v1/results/{id}`。
- `frontend/src/`：React 三维可视化、任务监控与优化展示。
- `deploy/`：容器化脚本与 Compose 配置。

## 法规合规声明与可替代实现

系统遵循最小权限原则，对外部命令施加白名单与路径沙箱，所有执行日志入库以满足审计要求。OpenFOAM、Fluent、Star-CCM+ 均可由适配层互换，若任一软件许可不可用，可启用 mock 网格器与求解器确保流程可复现。
